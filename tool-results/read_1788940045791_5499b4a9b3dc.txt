     9→## 1. 시스템 아키텍처 개요
    10→
    11→본 시스템은 **클라이언트 단일 페이지 애플리케이션(SPA) · 서버 API Routes · SQLite 데이터베이스** 3계층 아키텍처로 구성된다.
    12→
    13→```
    14→┌─────────────────────────────────────────────────────────────────┐
    15→│                     계층 1: 클라이언트 (SPA)                      │
    16→│                                                                   │
    17→│  Next.js App Router 단일 라우트(/) 기반 SPA                       │
    18→│  Zustand 전역 상태 ── AnimatePresence 화면 전환 ── 13 Screen     │
    19→│  Web Speech API TTS · CSS zoom 글꼴 확대 · 고대비 모드            │
    20→│  Service Worker 캐시(cache-first) → 오프라인 동작 보장            │
    21→└───────────────────────────────┬─────────────────────────────────┘
    22→                                │ fetch POST /api/logs
    23→                                │ fetch GET  /api/content
    24→┌───────────────────────────────▼─────────────────────────────────┐
    25→│                     계층 2: 서버 (API Routes)                     │
    26→│                                                                   │
    27→│  Next.js API Routes (App Router)                                 │
    28→│  /api/logs   ── POST: 세션 이벤트 로깅, GET: 최근 100건 조회       │
    29→│  /api/content── GET: 콘텐츠 섹션 조회                             │
    30→│  Prisma Client로 SQLite 접근                                     │
    31→└───────────────────────────────┬─────────────────────────────────┘
    32→                                │ Prisma Client
    33→┌───────────────────────────────▼─────────────────────────────────┐
    34→│                     계층 3: 데이터베이스 (SQLite)                  │
    35→│                                                                   │
    36→│  KioskContent  ── 교육 콘텐츠 (section, title, body, imageUrl)   │
    37→│  KioskLog      ── 세션 이벤트 로그 (sessionId, eventType, screen) │
    38→│  KioskSession  ── 세션 메타 (startedAt, endedAt)                 │
    39→│  로컬 파일 DB (db/custom.db) · 임베디드 · 무설정                   │
    40→└─────────────────────────────────────────────────────────────────┘
    41→```
    42→
    43→### 계층 간 통신
    44→
    45→| 출발 | 도착 | 프로토콜 | 용도 |
    46→|------|------|----------|------|
    47→| 클라이언트 → 서버 | `fetch POST /api/logs` | HTTP JSON | 화면 전환·세션 이벤트 로깅 |
    48→| 클라이언트 → 서버 | `fetch GET /api/content` | HTTP JSON | 콘텐츠 섹션 동적 조회 |
    49→| 서버 → SQLite | Prisma `db.kioskLog.create()` | SQLite 쿼리 | 로그 영속화 |

    56→### ADR-001: Zustand 상태 관리 선택
    57→
    58→| 항목 | 내용 |
    59→|------|------|
    60→| **결정** | 클라이언트 전역 상태 관리를 Zustand v5로 채택 |
    61→| **대안** | React Context API, Redux Toolkit, Jotai |
    62→| **근거** | ① **번들 크기**: Zustand ~1.1KB vs Redux ~7.4KB. 키오스크 초기 로딩 최적화에 유리. ② **보일러플레이트**: Context API는 Provider 중첩·useCallback 재렌더링 이슈 존재. Zustand는 `create()` 한 번으로 스토어 생성. ③ **선택적 구독**: `useKioskStore(s => s.currentScreen)` 형태로 필요 필드만 구독하여 불필요 재렌더링 방지. Context API는 value 객체 전체 구독. ④ **미들웨어**: `persist`, `devtools` 등 체이닝 가능. ⑤ **키오스크 특성**: 화면 전환·접근성 설정 등 전역 상태가 단일 스토어에서 관리되는 구조에 적합. |
    63→
    64→**스토어 구조** (`src/store/kiosk-store.ts`):
    65→
    66→```
    67→KioskState
    68→├── currentScreen: Screen          // 현재 화면 (13개 리터럴 유니온)
    69→├── history: Screen[]              // 뒤로가기 히스토리 스택
    70→├── sessionId: string              // 익명 세션 ID (개인식별정보 불포함)
    71→├── sessionStarted: boolean        // 세션 활성 여부
    72→├── isMobile: boolean              // 768px 미만 여부
    73→├── visitedScreens: Set<Screen>    // 방문 완료 화면 집합
    74→├── fontSize: 'normal'|'large'|'xlarge'  // 글꼴 크기 단계
    75→├── idleTimer: timeout|null        // 유휴 타이머 핸들
    76→├── ttsEnabled: boolean            // TTS 활성 여부
    77→├── highContrast: boolean          // 고대비 모드 여부
    78→├── navigateTo(screen)             // 화면 전환 + 히스토리 push + 로깅
    79→├── goBack()                       // 히스토리 스택 기반 뒤로가기
    80→├── goHome()                       // 메인 화면 즉시 이동
    81→├── startSession()                 // 세션 시작 (ID 생성, main 진입)
    82→├── endSession()                   // 세션 종료 (standby 복귀)
    83→├── resetIdleTimer()               // 120초 타이머 리셋
    84→├── setFontSize / setTtsEnabled / setHighContrast  // 접근성 설정
    85→└── setMobile / resetToStandby     // 플랫폼·상태 유틸리티
    86→```

    90→### ADR-002: Web Speech API TTS 선택
    91→
    92→| 항목 | 내용 |
    93→|------|------|
    94→| **결정** | TTS 음성 안내를 브라우저 내장 Web Speech API로 구현 |
    95→| **대안** | 서버 TTS SDK (z-ai-web-dev-sdk TTS, Google Cloud TTS, AWS Polly) |
    96→| **근거** | ① **오프라인 동작**: Web Speech API는 브라우저 내장 음성 엔진 사용. 네트워크 단절 시에도 음성 안내 가능. 서버 TTS는 API 호출 필수 → 오프라인 불가. ② **비용**: Web Speech API 무료. 서버 TTS는 건당 과금 (Google $4/1M 문자, AWS $4/1M 문자). 보건소 예산 제약. ③ **지연**: Web Speech API는 로컬 엔진 직접 호출 → <50ms 시작. 서버 TTS는 네트워크 RTT + 서버 처리 → 300~1000ms. 키오스크 즉각적 응답 요구. ④ **구현 단순성**: `SpeechSynthesisUtterance` 객체 생성 후 `speak()` 호출만으로 완료. ⑤ **제약 수용**: 음성 품질·언어 지원은 브라우저 의존. 한국어 음성은 Chrome·Samsung Internet 기본 탑재. 타겟 브라우저(Chrome 90+, Samsung Internet 17+)에서 한국어 음성 사용 가능. |
    97→
    98→**구현** (`src/hooks/use-tts.ts`):
    99→
   100→```
   101→useTTS({ autoSpeak?: boolean })
   102→├── speak(text)           // 임의 텍스트 읽기
   103→├── speakIntro()          // 현재 화면 intro 텍스트 읽기
   104→├── speakFull()           // 현재 화면 full 텍스트 읽기
   105→├── stop()                // 음성 정지
   106→└── useEffect: currentScreen 변경 시 autoSpeak=true && ttsEnabled=true면 speakIntro() 자동 호출
   107→```
   108→
   109→음성 파라미터: rate=0.85 (어르신 배려 느린 속도), pitch=1.0, volume=1.0, lang=ko-KR

   113→### ADR-003: CSS zoom 글꼴 확대 선택
   114→
   115→| 항목 | 내용 |
   116→|------|------|
   117→| **결정** | 글꼴 크기 확대를 CSS `zoom` 속성으로 구현 |
   118→| **대안** | Tailwind `text-*` 유틸리티 클래스 교체, CSS `font-size` 변수, `rem` 기반 `font-size` 조절 |
   119→| **근거** | ① **전체 비례 확대**: `zoom`은 요소와 모든 자손의 시각 렌더링을 비례 확대. 텍스트·패딩·마진·이미지·보더가 일관되게 확대되어 레이아웃 붕괴 없음. ② **Tailwind text-* 한계**: `text-lg`→`text-xl` 교체는 텍스트만 커지고 패딩·간격은 그대로 → 레이아웃 깨짐. 모든 컴포넌트의 모든 요소에 반응형 크기 적용 필요 → 유지보수 비용 과다. ③ **CSS 변수 한계**: `font-size` 변수는 텍스트만 확대. `padding`·`gap` 등은 별도 변수 필요. ④ **구현 단순성**: `el.style.zoom = '1.15'` 한 줄로 전체 확대. 3단계 (1.0, 1.15, 1.3) 전환 간단. ⑤ **브라우저 지원**: Chrome·Safari·Edge·Samsung Internet 완전 지원. Firefox 126+ 지원(2024년 6월). 타겟 브라우저 범위 내. |
   120→
   121→**구현** (`src/app/page.tsx`):
   122→
   123→```typescript
   124→useEffect(() => {
   125→  const el = containerRef.current;
   126→  if (!el) return;
   127→  const zoomValue = fontSize === 'normal' ? 1 : fontSize === 'large' ? 1.15 : 1.3;
   128→  el.style.zoom = fontSize === 'normal' ? '' : String(zoomValue);
   129→}, [fontSize]);
   130→```

   134→### ADR-004: useEffect + ref hydration 대응
   135→
   136→| 항목 | 내용 |
   137→|------|------|
   138→| **결정** | `zoom`·`high-contrast`·`bg-background`를 `useEffect`에서 `ref.current.style` / `ref.current.classList.toggle`로 적용 |
   139→| **대안** | 조건부 `className`·`style` prop 직접 사용 |
   140→| **근거** | ① **Hydration mismatch 문제**: `fontSize`·`highContrast` 등 Zustand 상태는 클라이언트 전용. 서버 사이드 렌더링 시 초기값(normal, false)으로 HTML 생성. 클라이언트에서 이전 세션 상태(persisted)가 복원되면 서버 HTML과 불일치 → hydration mismatch 경고·버그. ② **useEffect 해결**: `useEffect`는 클라이언트 마운트 후 실행 → 서버 HTML과 무관하게 DOM 조작. hydration 완료 후 안전하게 상태 반영. ③ **ref 직접 조작**: `classList.toggle`·`style.zoom` 직접 조작은 React 렌더링 사이클과 무관 → hydration 충돌 없음. ④ **일관성**: 동일 패턴으로 zoom·highContrast·bgBackground 세 가지를 통일 적용. |
   141→
   142→**구현** (`src/app/page.tsx`):
   143→
   144→```typescript
   145→const containerRef = useRef<HTMLDivElement>(null);
   146→useEffect(() => {
   147→  const el = containerRef.current;
   148→  if (!el) return;
   149→  const zoomValue = fontSize === 'normal' ? 1 : fontSize === 'large' ? 1.15 : 1.3;
   150→  el.style.zoom = fontSize === 'normal' ? '' : String(zoomValue);
   151→  el.classList.toggle('high-contrast', highContrast);
   152→  el.classList.toggle('bg-background', currentScreen !== 'standby');
   153→}, [fontSize, highContrast, currentScreen]);
   154→```

   158→### ADR-005: AnimatePresence 화면 전환 선택
   159→
   160→| 항목 | 내용 |
   161→|------|------|
   162→| **결정** | Framer Motion `AnimatePresence` + `motion.div`로 화면 전환 구현 |
   163→| **대안** | React Router (next-router), CSS transition, View Transitions API |
   164→| **근거** | ① **SPA 단순성**: 본 앱은 단일 라우트(/) 기반 SPA. URL 변경 없이 Zustand `currentScreen` 상태로 화면 전환. React Router는 URL 기반 라우팅 → 불필요한 복잡성. ② **자연스러운 exit 애니메이션**: `AnimatePresence`는 언마운팅 컴포넌트의 exit 애니메이션을 보장. CSS transition은 언마운트 즉시 DOM 제거 → exit 애니메이션 불가. ③ **선언적 API**: `initial`·`animate`·`exit` variants로 진입·유지·퇴장 정의. 코드 가독성 높음. ④ **성능**: Framer Motion은 `will-change: transform` 자동 적용, GPU 가속. 0.25초 트랜지션 성능 목표 충족. ⑤ **제어**: `mode="wait"`으로 이전 화면 퇴장 후 새 화면 진입 보장. 동시 전환 방지. |
   165→
   166→**구현** (`src/app/page.tsx`):
   167→
   168→```tsx
   169→const pageVariants = {
   170→  initial: { opacity: 0, y: 20 },
   171→  animate: { opacity: 1, y: 0 },
   172→  exit: { opacity: 0, y: -20 },
   173→};
   174→
   175→<AnimatePresence mode="wait">
   176→  <motion.div
   177→    key={currentScreen}
   178→    variants={pageVariants}
   179→    initial="initial"
   180→    animate="animate"
   181→    exit="exit"
   182→    transition={{ duration: 0.25, ease: 'easeInOut' }}
   183→  >
   184→    <ScreenRenderer screen={currentScreen} />
   185→  </motion.div>
   186→</AnimatePresence>
   187→```

   191→### ADR-006: SQLite 선택
   192→
   193→| 항목 | 내용 |
   194→|------|------|
   195→| **결정** | 데이터베이스를 SQLite (로컬 파일 DB)로 채택 |
   196→| **대안** | PostgreSQL, MySQL, MongoDB |
   197→| **근거** | ① **임베디드**: SQLite는 서버 프로세스 없이 애플리케이션에 임베디드. 별도 DB 서버 설치·구성·운영 불필요. 보건소 키오스크 환경에서 인프라 최소화. ② **무설정**: `DATABASE_URL="file:./db/custom.db"` 하나로 완료. PostgreSQL은 호스트·포트·사용자·비밀번호·SSL 설정 필요. ③ **성능**: 읽기·쓰기 모두 로컬 파일 I/O → 네트워크 RTT 없음. 키오스크 로깅(건당 <1ms)에 충분. ④ **Prisma 호환**: Prisma SQLite 클라이언트 완전 지원. 스키마 마이그레이션 `db:push`로 간단. ⑤ **배포 단순성**: DB 파일이 프로젝트 디렉토리 내 존재 → 별도 백업 인프라 없이 파일 복사로 백업. ⑥ **트레이드오프 수용**: 동시 쓰기 제한(단일 라이터), 클러스터링 불가. 키오스크 단일 인스턴스 환경에서는 문제없음. |
   198→
   199→**Prisma 스키마** (`prisma/schema.prisma`):
   200→
   201→```prisma
   202→model KioskContent {
   203→  id        String   @id @default(cuid())
   204→  section   String   @unique
   205→  title     String
   206→  body      String
   207→  imageUrl  String?
   208→  qrCodeUrl String?
   209→  updatedAt DateTime @updatedAt
   210→  createdAt DateTime @default(now())
   211→}
   212→
   213→model KioskLog {
   214→  id        String   @id @default(cuid())
   215→  sessionId String?
   216→  eventType String
   217→  screen    String?
   218→  detail    String?
   219→  createdAt DateTime @default(now())
   220→}
   221→
   222→model KioskSession {
   223→  id        String   @id @default(cuid())
   224→  startedAt DateTime @default(now())
   225→  endedAt   DateTime?
   226→}
   227→```

   261→### 3.2 공통 컴포넌트: ContentLayout
   262→
   263→모든 콘텐츠 화면(standby, main 제외)이 공유하는 레이아웃 래퍼.
   264→
   265→```
   266→ContentLayout({ title, children, notice })
   267→├── KioskHeader (뒤로가기 + 화면 제목 + 홈)

   586→### 8.1 개인정보 미수집 원칙
   587→
   588→| 항목 | 상세 |
   589→|------|------|
   590→| **입력 수집** | 이름, 주민등록번호, 전화번호, 이메일 등 어떠한 개인식별정보도 입력받지 않음 |

   592→| **로깅** | `sessionId`(익명), `eventType`, `screen`, `detail`만 기록. 사용자 식별 불가 |
   593→| **쿠키** | 인증 쿠키·추적 쿠키 미사용 |
   594→| **로컬 스토리지** | Zustand persist 미사용. 세션 종료 시 상태 초기화 |

   596→### 8.2 장비 통신 차단
   597→
   598→| 항목 | 상세 |
   599→|------|------|
   600→| **Bluetooth** | 미사용. Web Bluetooth API 미호출 |
   601→| **Wi-Fi** | 미사용. 장비와의 네트워크 통신 없음 |
   602→| **USB** | 미사용. WebUSB API 미호출 |
   603→| **NFC** | 미사용. Web NFC API 미호출 |
   604→| **의도** | 본 키오스크는 교육 전용. 실제 측정·장비 제어 수행 없음 |

   606→### 8.3 콘텐츠 보안 정책 (CSP)
   607→
   608→```
   609→Content-Security-Policy:
   610→  default-src 'self';
   611→  script-src 'self' 'unsafe-inline' 'unsafe-eval';
   612→  style-src 'self' 'unsafe-inline';
   613→  img-src 'self' data: blob:;
   614→  font-src 'self' https://fonts.gstatic.com;
   615→  connect-src 'self';
   616→  frame-ancestors 'none';
   617→```
   618→
   619→- `frame-ancestors 'none'`: 클릭재킹 방지
   620→- `connect-src 'self'`: 외부 데이터 전송 차단
   621→- `img-src data: blob:`: 인라인 이미지 허용 (QR코드 등)

   635→## 9. 성능 아키텍처
   636→
   637→### 9.1 빌드 타임 최적화
   638→
   639→| 기법 | 상세 |
   640→|------|------|
   641→| **Turbopack** | Next.js 16 기본 번들러. 증분 컴파일, HMR <100ms |
   642→| **Noto Sans KR 다이나믹 서브셋** | `next/font/google`으로 사용 글리프만 서브셋. 300~800 웨이트 중 실제 사용 분만 로드 |
   643→| **font-display: swap** | 폰트 로딩 전 시스템 폰트로 렌더. FOIT 방지 |
   644→| **Tree Shaking** | 사용하지 않는 shadcn/ui 컴포넌트·Lucide 아이콘 제외 |
   645→
   646→### 9.2 런타임 최적화
   647→
   648→| 기법 | 상세 |
   649→|------|------|
   650→| **Framer Motion will-change** | `motion.div`에 `will-change: transform` 자동 적용 → GPU 가속. transform·opacity만 애니메이션 → 페인트·레이아웃 미발생 |
   651→| **AnimatePresence mode="wait"** | 동시 두 화면 렌더링 방지 → 메모리·GPU 절약 |
   652→| **Zustand 선택적 구독** | `useKioskStore(s => s.currentScreen)` 형태로 필요 상태만 구독. 불필요 재렌더링 방지 |
   653→| **passive: true 이벤트** | touchstart·scroll 리스너 `passive: true` → 브라우저 스크롤 차단 방지 |
   654→| **이벤트 리스너 조건부** | `sessionStarted`일 때만 리스너 등록. 세션 외 불필요 리스너 제거 |
   655→
   656→### 9.3 이미지 최적화
   657→
   658→| 기법 | 상세 |
   659→|------|------|
   660→| **Lazy Loading** | 장비 이미지·위치 이미지는 화면 진입 시에만 렌더. `<img loading="lazy">` 적용 |
   661→| **정적 에셋** | `/public/kiosk-images/` 하위 이미지. CDN 캐시 가능 |
   662→| **SVG 아이콘** | Lucide React SVG 아이콘. 래스터 이미지 미사용 → 해상도 무관 선명 |
   663→
   664→### 9.4 Service Worker 캐시 전략
   665→
   666→```
   667→┌─────────────────────────────────────────┐
   668→│           Service Worker (sw.js)         │
   669→│                                          │
   670→│  ┌─────────────────────────────────────┐ │
   671→│  │  정적 에셋: Cache-First             │ │
   672→│  │  HTML, CSS, JS, Font, Image         │ │
   673→│  │  → 캐시 hit 시 네트워크 요청 없음    │ │
   674→│  │  → 캐시 miss 시 네트워크 fetch 후    │ │
   675→│  │    캐시 저장                         │ │
   676→│  └─────────────────────────────────────┘ │
   677→│                                          │
   678→│  ┌─────────────────────────────────────┐ │
   679→│  │  API 요청: Network-First            │ │
   680→│  │  /api/logs, /api/content            │ │
   681→│  │  → 네트워크 요청 우선                │ │
   682→│  │  → 네트워크 실패 시 캐시 폴백        │ │
   683→│  └─────────────────────────────────────┘ │
   684→│                                          │
   685→│  ┌─────────────────────────────────────┐ │
   686→│  │  오프라인 폴백                       │ │
   687→│  │  네트워크 단절 시 캐시된 페이지 반환  │ │
   688→│  │  → 핵심 교육 콘텐츠 열람 보장        │ │
   689→│  └─────────────────────────────────────┘ │
   690→└─────────────────────────────────────────┘
   691→```
