## 1. 시스템 아키텍처 개요

본 관리자 대시보드는 기존 키오스크 시스템과 **동일한 Next.js 애플리케이션** 내에 `/admin` 경로로 통합 배포된다. 3계층 아키텍처를 유지하며, 관리자 API Routes는 `/api/admin/*` 경로에 배치된다.

```
┌──────────────────────────────────────────────────────────────────┐
│                  계층 1: 클라이언트 (Admin SPA)                    │
│                                                                    │
│  Next.js App Router /admin/* 라우트 기반 SPA                        │
│  TanStack Query(SWR) ── shadcn/ui 폼/테이블 ── 12 화면             │
│  JWT 세션 쿠키 · RBAC 가드 · Zod 폼 검증                           │
└──────────────────────────────┬────────────────────────────────────┘
                               │ fetch /api/admin/*
┌──────────────────────────────▼────────────────────────────────────┐
│                  계층 2: 서버 (Admin API Routes)                    │
│                                                                    │
│  Next.js API Routes (App Router)                                   │
│  /api/admin/auth/*   ── 인증: 로그인, 로그아웃, 세션 검증            │
│  /api/admin/users    ── 관리자 계정 CRUD                             │
│  /api/admin/content  ── 키오스크 콘텐츠 CRUD                        │
│  /api/admin/measurements ── 측정 항목/장비 CRUD                    │
│  /api/admin/images   ── 이미지 업로드                                │
│  /api/admin/stats    ── 대시보드 통계                                │
│  /api/admin/audit-logs ── 감사 로그 열람                            │
│  인증 미들웨어 → RBAC 미들웨어 → 핸들러 → 감사 로그 기록             │
└──────────────────────────────┬────────────────────────────────────┘
                               │ Prisma Client
┌──────────────────────────────▼────────────────────────────────────┐
│                  계층 3: 데이터베이스 (SQLite)                       │
│                                                                    │
│  AdminUser     ── 관리자 계정 (이메일, 해시, 역할)                   │
│  AdminSession  ── 세션 토큰 (JWT, 만료)                             │
│  KioskContent  ── 키오스크 콘텐츠 (기존 + 확장)                     │
│  MeasurementItem ── 측정 항목 6가지                                 │
│  MeasurementEquipment ── 장비 상세 정보                              │
│  ContentSection ── 화면 내 섹션 단위 콘텐츠                         │
│  AuditLog      ── 감사 로그 (append-only)                           │
│  KioskLog      ── 키오스크 이벤트 로그 (기존)                        │
│  KioskSession  ── 키오스크 세션 (기존)                               │
└────────────────────────────────────────────────────────────────────┘
```

## 5. 실시간 업데이트 전략

### 5.1 아키텍처 개요

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│  관리자 대시보드   │     │   API 서버        │     │  키오스크 클라이언트│
│                    │     │                    │     │                    │
│  ① 콘텐츠 저장    │────▶│  ② DB 업데이트    │     │                    │
│                    │     │  ③ 감사 로그 기록 │     │                    │
│                    │     │                    │     │                    │
│                    │◀────│  ④ 200 OK 응답    │     │                    │
│  ⑤ UI 갱신        │     │                    │     │                    │
│                    │     │                    │◀────│  ⑥ SWR 재검증     │
│                    │     │  ⑦ 최신 데이터     │────▶│  ⑧ 리렌더         │
└──────────────────┘     └──────────────────┘     └──────────────────┘

시퀀스: ①→②→③→④→⑤ ... (비동기) ⑥→⑦→⑧
```

### 5.2 구체 전략

| 전략 | 구현 | 대상 | 갱신 주기 |
|------|------|------|-----------|
| **SWR 재검증** | `useSWR(url, fetcher, { refreshInterval: 5000 })` | 키오스크 클라이언트 | 5초 |
| **포커스 재검증** | `revalidateOnFocus: true` | 키오스크 클라이언트 | 창 포커스 시 |
| **TanStack Query 갱신** | `useQuery({ queryKey, staleTime: 0 })` | 관리자 대시보드 | 저장 후 즉시 |
| **낙관적 업데이트** | `useMutation + onMutate 캐시 업데이트` | 관리자 대시보드 | 즉시 (롤백 시 원복) |
| **수동 갱신 트리거** | `queryClient.invalidateQueries()` | 키오스크 + 관리자 | 버튼 클릭 시 |

### 5.3 대안 검토

| 대안 | 장점 | 단점 | 채택 여부 |
|------|------|------|-----------|
| WebSocket | 실시간 양방향 | 구현 복잡도, SQLite와 부적합 | ❌ |
| Server-Sent Events | 서버→클라이언트 단방향 | 연결 유지 오버헤드 | ❌ |
| **SWR 폴링** | 구현 단순, HTTP 표준 | 5초 지연 (허용 범위) | ✅ |
| Firebase Realtime | 완전 실시간 | 외부 서비스 의존 | ❌ |

## 6. 보안 아키텍처

### 6.1 다계층 보안 모델

```
┌─────────────────────────────────────────────────────────────┐
│                     보안 계층                                │
│                                                               │
│  Layer 1: 전송 계층    HTTPS (TLS 1.3)                       │
│  Layer 2: 인증 계층    JWT httpOnly 쿠키 + 세션 DB 검증      │
│  Layer 3: 권한 계층    RBAC 미들웨어 (역할별 엔드포인트 제어)  │
│  Layer 4: 입력 계층    Zod 스키마 검증 + 살균화              │
│  Layer 5: 데이터 계층   bcrypt 해싱 (cost=12) + 매개변수화 쿼리│
│  Layer 6: 감사 계층    모든 쓰기 작업 감사 로그 기록          │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 위협 모델 및 대응

| 위협 | 대응 |
|------|------|
| **무인증 접근** | JWT httpOnly 쿠키 + 세션 DB 이중 검증 |
| **권한 상승** | RBAC 미들웨어에서 역할별 허용 작업 하드&코드 매핑 |
| **CSRF** | SameSite=Strict 쿠키 + CSRF 토큰 (동일 출처만) |
| **XSS** | React 기본 이스케이핑 + 이미지 URL 화이트리스트 |
| **SQL 인젝션** | Prisma 매개변수화 쿼리 (자동 방어) |
| **브루트 포스** | 로그인 5회 실패 시 15분 계정 잠금 |
| **세션 탈취** | httpOnly + Secure + SameSite=Strict, 8시간 만료 |
| **파일 업로드 악용** | 화이트리스트 확장자(.png/.jpg/.webp/.svg), 5MB 제한, 메타데이터 제거 |

### 6.3 CORS 정책

```
관리자 대시보드: 동일 출처 (Same-Origin)
키오스크 클라이언트: 동일 출처 (Same-Origin)
→ Next.js 단일 애플리케이션이므로 CORS 불필요
→ 외부 도메인 접근 차단
```

```
│ → 필드 에러 표시  │    │ → 로그인 리다이렉트│    │ → 503 응답        │
│                    │    │ 권한 에러 (403)   │    │ Prisma 에러       │
│ 네트워크 에러      │    │ → 권한 없음 토스트 │    │ → 500 응답 + 로그  │
│ → 재시도 UI       │    │ 검증 에러 (400)   │    │                    │
│                    │    │ → 에러 메시지 응답 │    │ 파일 시스템 에러   │
│ TanStack Query    │    │ 충돌 에러 (409)   │    │ → 업로드 실패 UI   │
│  자동 재시도      │    │ → 충돌 해결 UI    │    │                    │
└──────────────────┘    └──────────────────┘    └──────────────────┘
```

### 8.2 API 에러 응답 형식

```typescript
interface ApiError {
  error: string;          // 에러 메시지 (한국어)
  code: string;           // 에러 코드 (AUTH_INVALID, RBAC_DENIED, ...)
  details?: Record<string, string[]>; // 필드별 검증 에러
}
```

## 9. 확장 포인트

| 영역 | 현재 | 향후 확장 (v2) |
